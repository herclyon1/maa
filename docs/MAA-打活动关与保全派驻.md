# MAA 打活动关与保全派驻

**这份文件存在的理由**：2026-08-23 指挥打活动关卡了整整一天，全部时间花在
「我不懂，一直在摸索」。2026-09-04 用户原话：「要不然的话，每次都是重搞。」
所以下面写的是**照着做就能做**的顺序，不是背景介绍。动手前先读完对应那一节。

先记住一句话，上次那一天的三次翻车都是它的不同穿法：

## 一、打活动关

活动关有两件完全不同的事，先分清要哪一件。

### 1. 只是刷活动关拿素材 → 改配置，不碰作业

这条路走的是 AUTO-MAS 的日常队列，手机页「明日方舟」那段就能改。

| 想要的 | 改哪一项 | 注意 |
|---|---|---|
| 天天刷某个活动关 | `Info.Stage` 填关卡号（如 `AT-4`） | **活动一结束这关就不存在了**，固定关指着它会让之后每趟都失败 |
| 活动期间自动刷活动关，结束自动回落 | `Task.IfActivityFirst` 打开 + `Task.ActivityStageIndex` | 序号数的是活动关卡列表**从上往下的位置，第一关填 1**，不是 0 |
| 活动那趟吃几瓶药 | `Task.ActivityMedicineNumb` | **和常规的 `Info.MedicineNumb` 是两处**，改错一处等于没改 |

* 2026-08-26「826 事故」的元凶就是 `活动关优先` 开着而序号理解错，刷错关还烧了药。
  改之前先用 `winrun.sh --py scripts/mac/lib/effective_config.py` 看**真正生效**的那份。
* 当前设置：固定 `1-7`、活动关优先 `false`、理智药 `0`。

### 换到新活动的关卡后：**先更新 MAA，否则 Fight 直接拒收**

改完 `Info.Stage`（比如从 `1-7` 改成 `SR-5`）不要以为就完了。MAA 认不认这个
关卡号，取决于它的**资源版本**——新活动上线后要更新才有那一份关卡数据。

认不出来的样子（2026-09-04 实测）：`append_task` 返回的 **task id 是 0**，
`asst.start()` 照样返回 True、一秒钟"跑完"，什么都没发生。
`D:\ark\maa\debug\asst.log` 里写得很清楚：

```
Unknown task: SR-5 / Task SR-5 not found
The stage name is not in invalid, or is not main line stage SR-5
Cannot set stage SR-5
```

**验证的正门**（不吃药、不白刷）：

```bash
scripts/mac/winrun.sh --timeout 400 --py1 scripts/windows/copilot-run.py \
  'C:\ProgramData\fight.log' fight SR-5 1
```

`fight` 模式的药量写死 0。看日志里 `Fight 已下发 id=` 后面那个数：
**0 就是没认出来，非 0 才是认了**。真打通了会有
`StageDrops ... "stageCode": "SR-5" ... "stars": 3`，那才算验完。

**更新的正门是中继自带的预更新**，别手动去替换 `resource/stages.json`
（只换那一个文件不够，MAA 还要在 tasks.json 里找关卡的导航定义，照样拒收）：

```python
sys.path.insert(0, r"C:\ProgramData\ark-relay")
from ark_relay import preupdate
preupdate.run_maa(Path(r"D:\ark\maa"), budget_s=600, problems=[])
```

用 `winrun.sh --py1` 跑它（要交互桌面）。2026-09-04 实测 v6.17.0 → v6.17.1，
`stages.json` 803222 → 807286 字节，Fight 立刻就认 SR-5 了。

手动起 MAA 的话必须带参数，否则一启动就自动开跑：
`scripts/mac/wingui.sh launch 'D:\ark\maa\MAA.exe -- --skip-startup-auto-run'`

### 活动的奖励弹窗：只挡作业模式，不挡 Fight

月行水上每次通关会掉塔罗牌，并在**地图上**弹一个大动画。

* **作业（Copilot）模式会被它挡死**：每打完一关要回地图找下一关，弹窗糊在
  地图上，MAA 就一直 `Copilot@ChapterSwipeToTheRightAndPlot` 找不到关卡。
  2026-09-04 打 SR-5〜SR-8 时卡过两次，**人点掉弹窗它立刻自己接上**。
* **Fight 模式不受影响**：终端 → 活动 → 关卡 → 打 → 结算 → 「再来一次」，
  全程不回地图。实测那趟掉了塔罗牌「节制」，MAA 照样正常结算收尾。

所以队列里刷活动关（走 Fight）不用管这个弹窗；只有我手动用作业连打时要盯着。

### 导航突然失败先看是不是掉线了

`SwipeToStage` 滑几下就没下文、停在别的关卡页，**先截图看是不是
「登录认证已失效，请重新登录」**。账号在别处登录会把模拟器这边挤下线，
画面还停在旧界面，看着特别像导航坏了。跑一次 `copilot-run.py <log> startup`
重登即可，见 memory `game-relogin-is-just-restart`。

### 2. 要通关（EX、突袭、剧情关）→ 用作业（Copilot）

#### 作业从哪来

* **prts.plus 的神秘代码**，粘进 MAA 的自动战斗框；或
* **本地 JSON**：`D:\ark\maa\config\copilot\`（48 个）和 MAA 自带的 `resource\copilot\`。
* 2026-08-22 实测：`prts.plus` 和 MAA 真正调用的 `prts.maa.plus/copilot/get/<id>` 从游戏机都通；
  **`prts.wiki` 从那台机器 403**，两者别混为一谈。

#### 用接口批量拿作业（Mac 上 curl 直连就通，不用开浏览器）

```bash
# 找某个活动的全部作业：levelKeyword 填活动代号（如 act54side）
curl -s 'https://prts.maa.plus/copilot/query?page=1&limit=100&levelKeyword=act54side'

# 下载一份完整作业
curl -s 'https://prts.maa.plus/copilot/get/<id>'
```

**这两个接口返回的东西不一样，用错了会浪费半小时**（2026-09-04 栽过）：

| 接口 | `content` 里有什么 |
|---|---|
| `query` | 只有 `doc` / `opers` / `groups` / `stage_name`——**没有 `actions`** |
| `get` | 完整作业，**含 `actions`**（真正的部署动作在这里） |

`query` 是给列表页用的，作业正文被裁掉了。拿它的 `content` 存成文件喂给 MAA，
MaaCore 会**在 `append_task` 阶段就拒收**，返回的 task id 是 **0**，
而 `asst.start()` 照样返回 True、一秒钟就"跑完"了，什么都没发生。

排错的正门是 **`D:\ark\maa\debug\asst.log`**，它写得很清楚：

```
[ERR] Json parse failed <路径> invalid map<K, T> key
[ERR] CopilotConfig parse failed
[ERR] asst::Assistant::append_task | invalid params: {...}
```

**`append_task` 返回 0 就是参数被拒**，别去猜是哪个字段——先看这三行。
2026-09-04 我挨个试了 11 种参数组合全被拒，其实一行日志就说明了是作业文件的事。

挑作业按 `views` 排序、看 `rating_level`（满分 10）和 `rating_ratio`；
作者在 `doc.details` 里会写清楚这关能不能自动，**那句话要读**——
月行水上的 SR-4 就是 5 份作业的作者一致说"MAA 会被剧情卡住，只能手动"。

#### 从哪个界面启动——上次翻车的主要来源

| 模式 | 必须停在这个界面 |
|---|---|
| 单份作业 | 编队界面，有 **开始行动** 那个 |
| 多作业 / 战斗列表 | **关卡所在的地图界面**，不是编队界面 |
| 保全派驻 | 手动准备完，停在 **开始部署** |
| 悖论模拟 | **关掉自动编队**、手动选好技能，停在 **开始模拟** |

多作业模式里所有关卡必须在同一区域（只靠左右滑地图能到）。
理智不足、打输、非三星结算，任何一条都会让队列停下。

#### 走通一次活动 EX 的配方（2026-08-23 实测有效）

1. 先跑 MAA 的 `StartUp` 任务，让它自己把游戏开到主界面。**不要手动掐时间等开机**。
2. **手点**进活动地图（横幅 → 分区）。这一步安全，正是因为第 1 步保证了起点界面。
3. 再用 `copilot_list` 跑，它在活动地图内部能导航。
4. 遇到 `BattleFormationTask` + `reason: Missing`，换这一关的下一份作业。

失败过的四种假设，别再犯：

| 我当时假设的 | 实际 |
|---|---|
| `filename` 模式会自己找路 | 不会。它只认编队界面，别处启动直接错在 `BattleStartAll`。会找路的是 `copilot_list` |
| 从主界面能导航到活动关 | 不能。它会去翻主线章节——曾经翻了 224 次滑动、100 次翻章去找 AT-5 |
| 连按几次返回能回到中性界面 | 主界面按返回会弹「是否确认退出游戏」，用来关掉它的那一下点开了活动商店，两次 |
| MAA 能导航到任何关卡 | 它找不到这个活动的 **EX** 图。手点过去再用 `filename` 模式，一次就过 |

#### 自动编队被拒绝时——看 `reason`，不要看 `why`

外层永远写 `"why": "OperatorMissing"`，有用的是 `details.opers` 里的 `reason`：

| `reason` | 含义 | 解法 |
|---|---|---|
| `Unavailable` | 干员**有，也找到了**。是作业写了练度要求（通常是专精等级）没达到 | 设 **`ignore_requirements: true`** |
| `Missing` | MAA 在列表里根本没找到这个干员 | **取消这个干员的「特别关注」**（官方 FAQ 原话） |

* `ignore_requirements: true` 是**默认做法**：练度要求是作业作者的偏好，不是游戏的限制。
  2026-08-23 三个被拒的干员全都是有的，加上这个参数后同一份作业直接凑齐六人开打。
* `Missing` **不等于没这个干员**。上次就是这么读的，白扔了两份能用的作业。
* 排查时**不许截断回调日志**——区分这两种情况的字段就在 260 字之后。

#### 关内剧情把 MAA 卡住时：MAA 救不回来，只能自己放人

有些关卡**战斗中会反复弹关内对话**（月行水上 SR-4 是每来一辆告解车播一次，
还带「往左/往右」选项）。作业站上这类关的作业，作者一般都会在
`doc.details` 里写明——SR-4 那 5 份作业的作者**全都**独立写了
"本关没办法自动""MAA 直接瘫痪""被剧情卡住没招"。**这句话要当真。**

**MAA 为什么救不回来**（2026-09-04 实测，三种时序都试过）：
它发出第一个 `CopilotAction: Deploy` 后进入 `Copilot@WaitUntilEndOfAction`，
剧情一挡住战场，它就再也认不出状态，**固定 58 秒后**抛 `TaskChainError` 退出。

* 给作业加 `pre_delay` **没用**：设 25 / 60 / 100 秒，超时都还是在发出 Deploy
  之后 58 秒发生——那个超时和 pre_delay 是两回事，不会因为它在等而延后。
* **先清剧情再启动 MAA 也没用**：MAA 会放弃当前这局、从地图重新导航进关，
  剧情原样再来一遍。
* **它发出 Deploy 后立刻清剧情也没用**：16 秒清完、它还有 42 秒才超时，
  屏幕早就干净了，它照样不动作直到超时。

**所以这类关只能自己放人**，工具都已经做好了：

| 要做什么 | 用什么 |
|---|---|
| 把作业的 `location: [x, y]` 换算成屏幕像素 | `scripts/mac/lib/tilepos.py`（照抄 MAA 的 `TileCalc2`） |
| 关卡的格子表和相机参数 | 游戏机 `D:\ark\maa\resource\Arknights-Tile-Pos\<stage>-*.json` |
| 真正把干员拖到格子上 | `scripts/windows/deploy.py`（走 MAA 自带的 MaaTouch） |

**部署的三个要点**（都是踩出来的，缺一个就放不下去）：

1. **起手要竖直向上把干员从卡槽里拉出来**（约 120px），再走向格子。
   直接从卡片斜着拖，起手就滑出了卡片区域，游戏当成在滑干员列表。
2. **一次连续触摸走完**。"拖到格子松手 → 再按一次选朝向"是错的，
   第二次按下＝取消这次部署。
3. 松手后游戏停在**选朝向**那一屏，那一下用普通 `adbdo.sh swipe` 补完即可。
   高台上的干员**显示得比格子中心高约 115px**，朝向要从显示位置往外甩。

判断有没有放上去：看**干员卡还在不在**、费用有没有扣、"剩余可放置角色"有没有减。

**不要用 `adb shell input swipe` 部署**：它是匀速直线，游戏根本不认；
`input motionevent` 要 Android 11+，而这台雷电是 **Android 9**，没有这个命令。

**反复试是不花理智的**（2026-09-04 实测核对过理智数值）：

* **放弃行动全额返还**，弹窗上会写「放弃行动将会恢复 N 理智（全部返还）」。
* **打到任务失败也不扣**。当时我看结算页上"任务失败"没有返还标记，
  就以为扣了，还写进了这份文档——**是错的**。后来回关卡页读理智：
  打完前 5 关时 169，一小时四十八分钟后是 185，和纯自然恢复（每 6 分钟 1 点）
  只差 2 点，中间十几次进出 SR-4 一点没少。
  **不要凭结算页的观感推断，回关卡详情页读那个数字。**

所以这类关可以放心反复试。关卡详情页还有个「**演习**」按钮同样不消耗理智，
战场和正式的完全一样，好处是不用等结算动画，调坐标时更快。

#### 突袭（EX 关的第二难度）

* 从关卡详情页底部的 **突袭模式** 切，标题变红、多一条附加条件、按钮变 **开始突袭**。
* **突袭是一星结算，这是对的**，突袭没有三星。拿三星当成功判据会把好好的一趟报成失败。
* 作业用 `difficulty` 声明支持哪种：`1` 普通、`2` 突袭、`3` 都行、`0` 没写。
* 作业站把突袭变体单独编号，形如 `act44side_ex08#f#`。

日达诺夫园区**只有这一份**。荒废灯塔挑一份能凑出核心干员的。

### 先看有没有「全权委托」——有就别手打

**这是最省时间的一条，优先走它。**（用户 2026-09-04：「如果有自动通关就用那个东西。」）

* 解锁条件：**在当前派驻周期内、用不含助战的阵容打通至少一层**，那张图的
  全权委托才会亮；没打过的图上面挂着锁。
* 代价：每次 **2 张常态事务代理卡**，奖励按**本周期到达过的最高层数**给。
* 所以顺序是：先手打一次把层数推到 6/6（或推到你满意的层），
  之后同一周期内全靠委托，一次 2 张卡，几秒钟拿满奖励。
* 2026-09-04 实测：荒废灯塔本周期最高 6 层，一次委托拿到
  数据增补条 ×20、增补仪 ×10，耗时几秒。

界面位置：关卡详情页右下角，「开始保全作战」左边的小方块。勾上之后
按钮上会出现 `PRTS -2` 的角标，点下去弹确认框，里面写着预计奖励和卡的余量。

### 保全派驻和普通作业的四点不同

1. **`自动编队` 对保全无效**（官方文档原话）。编队必须手动。
2. 必须**手动完成初始任务准备**，一直做到关卡详情里出现 **开始部署** 按钮，才能让 MAA 接手。
3. **导能元件**要按作业写的那个选（上表「导能元件」列）。
4. **战术装备**按作业的 A/B 表选。

工具人怎么选（几份作业的说明里反复强调的同一批要求）：

* 练度**最好精二，最低精一满级**；优先**费用低**的。
* 技能不要选**只能开一次**的（山二技那种）、不要选**接敌才放**的（锏三技那种）、
  不要选**攻击范围奇怪**的（黑三技那种）——否则 MAA 会一直放技能。
* 医疗最好流明，狙击最好速狙，先锋要求能站场。
* 别多带辅助，别带小车。

### 怎么走到保全派驻（别走待办那条路）

**终端 → 底部「常态事务」那一栏 → 保全派驻 → 进入。**

底部导航从左到右六个格子，常态事务在 x≈930 那个。别走首页待办里的快捷入口：
待办的内容会变，2026-09-04 我按记住的坐标点过去，进的是**集成战略**，
差一点碰到「放弃本次探索」。进错了就用左上角返回退出来，探索不会丢。

### 领奖励：有三处，别只领一处

1. **周期任务**（列表页右上角那个按钮）：通关某张图、达到 N 层若干次，一张张领。
2. **周期清理记录**（关卡页**右上角**那块，标着 BEST RECORD n/6）：
   点开是 1/6…6/6 的阶段奖励，顶上有 **一键领取**。
   有奖励可领时那块的右上角有个**橙色小菱形**角标。
   2026-09-04 我漏了这处，用户提醒才发现，一次领到模组数据块 ×5、
   数据增补仪 ×10、数据增补条 ×30。
3. **报酬进度条**（关卡页左下）：数据增补条／增补仪是**自动入账**的，
   那两条只是本周期的上限进度，点「查看酬劳明细」只有说明，没有领取按钮。

### 全权委托：奖励为 0 时按钮是锁死的

上限满了之后再开委托，确认框里「预计可获得」全是 ×0，这时 **确认使用点不动**
（同一个框里的「取消」点得动，所以不是点击没生效，是游戏不让你白花卡）。
想再刷周期任务的次数，只能真打一趟。

### 手动准备的实操顺序（2026-09-04 全程走通一次，按这个来）

1. 派驻列表页 → 点那张图的**缩略图**（点标题条不管用）。
2. 关卡详情页 → **开始保全作战**。
3. **第 1 步 选定向导能元件**：按作业要的那个选（见上表），右下角 **确认选择**。
4. **第 2 步 战术装备**：八个格子按作业的 A/B 表点。
   顺序是 `先锋 重装 术师 辅助 / 近卫 狙击 医疗 特种`——
   这个顺序是拿两份作业的 equipment 数组交叉验证出来的，不是猜的。
   右下角 **装备确认**。
5. **第 3 步 首批作战小队选任**：右上 **快捷编队** 打开选人界面 →
   左下 **清空选择** → 右上 **职业** 展开兵种栏 → 按兵种挑够数 → **确认**
   → 回到小队页按 **阵容确认**。
6. 第一次进这张图会弹一页教程，左上 **关闭**。
7. 到这里就是有 **开始部署** 按钮的那一屏了，**MAA 从这里接手**。

选人界面的两个坑：
* 网格是**按列排**的：位置 n 在第 `⌈n/2⌉` 列、奇数在上排偶数在下排。
  已选的会被顶到最前面，所以**永远点「已选数量+1」那个位置**最稳，
  点完它不动，后面的也不动。
* 横向滚动**有惯性**，一甩就冲过头。要精确挪列就用**慢速小步**
  （距离 180 像素、时长 900 毫秒），一步一列。

### 让 MAA 接手的两条路

* **图形界面**：自动战斗 → 导入本地 JSON 作业 → 确认关卡名对 → 开始。
* **无窗口**：直接调 MaaCore 的 **`SSSCopilot`** 任务（和普通作业的 `Copilot` 是**两个不同的任务**）：

```json
{ "enable": true, "filename": "sss/plan.json", "loop_times": 1 }
```

`filename` 绝对相对路径都行，**不支持运行期设置**。
可以设 `loop_times`；但 **MAA 不借干员**，需要借助战就别用循环。

跑它的三个实操要点（2026-09-04 踩出来的）：

1. **进程里要先 `os.chdir` 到 MAA 目录**，否则 DLL 找不到，脚本静悄悄地死。
2. **不能用 `subprocess.Popen` 脱离启动**：winrun 是靠计划任务跑的，
   任务一结束会把整棵进程树连坐杀掉，日志一个字都不会写。
   正确做法是**再注册一个独立的计划任务**（`schtasks /create` + `/run`），
   它归任务计划程序管，和 ssh 会话没关系。
3. 脚本自己**别提前返回**：Asst 一被回收，战斗当场停。一趟保全要
   二三十分钟，循环等到链事件（`TaskChainCompleted`）再退出。

跑起来之后日志里会看到 `SSSStage {"stage": "LT-1"}`、
`CopilotAction {...}`，那就是真在打了。打完一整套会连着出
`SSSGamePass {}` 和 `链 TaskChainCompleted SSSCopilot`——**这两行才算通关**。

`SSSStage` 同一层会重复出现（MAA 每隔几分钟重新识别一次），
**不是失败重开**。判断有没有翻车看命数和敌人计数，别看这一行的次数。

一趟六层约 20 分钟：2026-09-04 实测 LT-1 到 LT-6 用了 01:16→01:56。

## 三、两件事共同的红线

* **`自动编队` 会清空当前编队**，按作业的干员表重建。别在一个你在乎的编队上跑。
* **AUTO-MAS 挂不了作业**：它的 MAA 集成只有 `IfFight`、`IfSeizeEntrustTask`、
  `SanityTaskType`、`TaskTransitionMethod`，**没有作业字段**，所以进不了夜里的队列。
  只能手动或走 MaaCore。
* **硬性前提**：模拟器 60 FPS（**2026-09-04 由 MaaCore 的回调实测确认**：
  `EmulatorFPS {"fps": 60}`，以前文档里写的「无法确认」已作废）+
  触控模式 MiniTouch 或 MaaTouch。**普通 adb `input tap` 不算**，部署是带方向甩动的
  按住—拖—松开，帧级时序，手点那套做不到。
* **判断卡住看重复，不看安静**：找不到关卡的导航会一直吐回调，静默计时器永远不触发。
  `scripts/windows/copilot-drive.py` 的做法是数连续相同子任务，30 次就放弃。
* 别直接启动 `MAA.exe`（它是启动器），走既有脚本。
