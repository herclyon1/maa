# 运维手册

## 连接

```bash
ssh Administrator@$ARK_HOST
```

走 Tailscale，不需要端口转发。两端登录同一个 Tailscale 账号即可。

## 远程截图

SSH 会话没有桌面，必须通过计划任务在交互式会话里截：

```bash
ssh Administrator@$ARK_HOST 'schtasks /run /tn "ark-shot"'
sleep 4
scp Administrator@$ARK_HOST:'C:/ProgramData/ark-shot.png' ./now.png
```

## 远程操作（点击 / 输入 / 启动程序）

写动作文件 → 上传 → 触发：

```bash
cat > cmd.txt <<'EOF'
run D:\Users\Administrator\Desktop\AUTO-MAS\AUTO-MAS.exe
sleep 20000
click 264 345
sleep 2500
shot C:\ProgramData\s1.png
monitoroff
EOF
scp cmd.txt Administrator@$ARK_HOST:'C:/ProgramData/ark-cmd.txt'
ssh Administrator@$ARK_HOST 'schtasks /run /tn "ark-do"'
```

支持的动作：

| 动作 | 说明 |
|---|---|
| `move x y` | 移动鼠标 |
| `click x y` / `rclick x y` / `dclick x y` | 左键 / 右键 / 双击 |
| `scroll x y n` | 在 (x,y) 处滚轮 n 格（正数向上、负数向下；2026-08-20 新增——Electron 页面吃不进 PgDn/PgUp，翻页只能靠它） |
| `type <SendKeys>` | 键盘输入，如 `type {ESC}` |
| `sleep <毫秒>` | 等待 |
| `run <路径>` | 启动程序 |
| `shot <路径>` | 全屏截图 |
| `monitoroff` | 关闭显示器（**放在最后**，之后任何鼠标动作都会把它唤醒） |

## 查看 / 修改游戏配置的正确入口（2026-08-20 教训）

**永远从 AUTO-MAS 的 UI 进（`run AUTO-MAS.exe` 会聚焦已运行的实例），不要直接双击 MAA 或 MaaEnd**——
那两个是"启动器"，直开会连带拉起雷电模拟器/终末地本体（8/20 就这么误开了一次模拟器，
只好 taskkill dnplayer.exe + Ld9BoxHeadless.exe 收场）。

**UI 与 JSON 谁是权威：** 磁盘上的 `config/ScriptConfig.json` 等是机器跑任务时读的权威；
但 **AUTO-MAS 运行中内存里持有一份，UI 保存时会整体回写**——AUTO-MAS 开着时直接改 JSON
会被覆写（8/20 实测：JSON 已改药量 0，UI 仍显示旧值 999，一保存就会写回 999）。规矩：

- AUTO-MAS **开着** → 一律走 UI 改（编辑页没有保存按钮，点右上「返回」即落盘）
- AUTO-MAS **关着**（收件箱在开机早期应用就属于这种）→ 才可以直接改 JSON
- 改完一律回读 JSON 核对（`MedicineNumb`、`Stage` 等字段）

执行日志：`C:\ProgramData\ark-do.log`

## 查看运行记录

AUTO-MAS 每轮跑完写一份结构化记录：

```
D:\Users\Administrator\Desktop\AUTO-MAS\history\<日期>\<用户名>\<时-分-秒>.json
```

文件名 = 开始时间，文件修改时间 = 结束时间。内容：

```json
{
  "drop_statistics": {},
  "recruit_statistics": {},
  "sanity": 1,
  "sanity_full_at": "理智将在 2026-08-15 04:11 回满。(20h 44m 后)",
  "maa_result": "Success!",
  "maaend_result": "MaaEnd 部分任务执行失败: ⚔️协议空间"
}
```

同目录下的 `.log` 是完整运行日志。

读取时注意编码：文件是 UTF-8，但**路径里的中文目录名**经 SSH 返回时是 GBK。

## 检查机器有没有正常跑

```bash
ssh Administrator@$ARK_HOST 'powershell -NoProfile -Command "
  (Get-Date).ToString(\"yyyy-MM-dd HH:mm:ss\");
  (Get-CimInstance Win32_OperatingSystem).LastBootUpTime;
  Get-Process AUTO-MAS -ErrorAction SilentlyContinue | Select-Object StartTime
"'
```

开关机历史（用来核对 BIOS 唤醒时间是否生效）：

```powershell
Get-WinEvent -FilterHashtable @{LogName='System'; Id=6005,6006,1074} -MaxEvents 40 |
  ForEach-Object { $_.TimeCreated.ToString("MM-dd HH:mm:ss") + "  " + $_.Id }
```

`6005` = 开机，`6006` = 关机完成，`1074` = 关机请求。

## 改远程配置的标准流程

**永远不要直接在远端用正则改 JSON。** 流程：

1. 下载：远端 `[Convert]::ToBase64String([IO.File]::ReadAllBytes($f))` → 本地解码
2. 本地改（定位到目标块的文本范围内替换，不要全局替换）
3. 本地 `json.loads()` 校验
4. **结构化 diff**：改动前后都拍平成 `路径 → 值`，检查"新增 0 / 删除 0 / 改动 N"
5. 远端备份 `copy /Y ... .bak-YYYYMMDD`
6. `scp` 上传
7. 远端回读并再次 `ConvertFrom-Json` 校验

第 4 步不能省。见 [踩过的坑](05-踩过的坑.md#正则改-json-漏改并误伤)。

## 操作 macOS 上的 PlayCover 游戏

用 computer-use 驱动 PlayCover 里的 iOS 游戏（明日方舟等）时，有三条硬规矩，
都是实操中撞出来的：

**① 必须慢速按压，普通点击无效**

PlayCover 把鼠标事件翻译成触摸事件，一次性的 `left_click` 常常不被识别。
必须拆成：

```
mouse_move → left_mouse_down → 等 1 秒 → left_mouse_up
```

游戏内**所有**点击都要这样，包括关闭弹窗的小 X。曾经连点三次同一个关闭按钮
都没反应，换成慢速按压后一次成功。

**② 滚动无效，要用拖拽手势；而且要分清方向**

`scroll` 和一次性的 `left_click_drag` 都不管用，必须手动分解：

```
mouse_down → 中间插入 2~3 个 mouse_move → mouse_up
```

方向容易搞反，记牢：

| 拖拽方向 | 看到的内容 |
|---|---|
| 从右往左拖（1150 → 500） | 往**右**看（列表后面的内容） |
| 从左往右拖（500 → 1150） | 往**左**看（列表前面的内容） |

**③ 横向列表必须一屏一屏核，不能一口气滑到底**

活动商店是横向滚动的。连续三次大幅滑动会直接跳到最右端，**中间整整两屏被跳过**。
曾经因此漏掉一半商品，还报告说"已经搬空"。

正确做法：滑到最左端 → 截图 → 滑**一屏** → 截图 → 重复，直到最右端。
每屏都要看清才算数。

**④ 买东西之前先把全部清单看完**

代币有限时，先买的东西决定了后面买不到什么。曾经先买了家具（695 代币），
才发现后面还有更重要的作战记录和技巧概要，而代币已经不够了。

## 常见故障

| 现象 | 检查 |
|---|---|
| SSH 连得上但立刻断开、无 banner | 杀毒软件是否隔离了 `sshd-session.exe`。**这种情况只能人到现场** |
| 到点没跑 | AUTO-MAS 进程在不在；`AUTO-MAS_AutoStart` 计划任务在不在；机器有没有登录到桌面 |
| 「协议空间」失败 | 是不是有人正用 ToDesk 连着（被控端面板遮挡） |
| 通知一条都收不到 | AUTO-MAS 的通知是三层开关，见 [配置清单](02-配置清单.md) |
| 企业微信 `errcode=60020` | 调用方 IP 不在「企业可信IP」里 |
| 模拟器启动了但是错的实例 | 模拟器类型必须 `ldplayer` + `ldconsole.exe` |

## 电源

```powershell
powercfg /q SCHEME_CURRENT SUB_VIDEO VIDEOIDLE     # 显示器超时
powercfg /q SCHEME_CURRENT SUB_SLEEP STANDBYIDLE   # 整机睡眠（必须是 0）
powercfg /requests                                  # 谁在阻止休眠
powercfg /lastwake                                  # 上次是被什么唤醒的
```

**显示器休眠不影响任务，整机睡眠会中断一切。**

## 中继是 Windows 服务，不是计划任务

2026-08-16 起，中继由服务控制管理器守护，不再靠计划任务拉起。

```bash
sc query ark-relay          # 看状态
sc stop  ark-relay          # 停（维护时用）
sc start ark-relay          # 起
sc qfailure ark-relay       # 看恢复动作
```

**恢复动作**：意外终止后 3 秒自动重启，重置周期 60 秒。SCM 持有进程句柄，
进程一退出内核立刻通知，没有轮询间隔。

**故意留着的三个口子**——它们都需要明确的管理员命令，不会自己发生，而且
是维护更新中继的唯一通道，不要堵：

```
sc stop ark-relay                    停止（恢复动作对「主动停止」不生效，这是 Windows 的设计）
sc config ark-relay start= disabled  禁用开机自启
sc delete ark-relay                  删除服务
```

**更新中继代码的正确姿势**：

```bash
sc stop ark-relay
scp 新文件 → C:/ProgramData/ark-relay/ark_relay/
sc start ark-relay
```

**回滚成计划任务**：`sc delete ark-relay`，再 `schtasks /change /tn ark-relay /enable`
（那个任务还在，只是禁用了，留作后路）。

### 中继同时守护 AUTO-MAS

AUTO-MAS 做不成服务：它要驱动模拟器和游戏窗口，而服务在 session 0 没有桌面。
所以由中继每 120 秒检查一次，不在就拉起。

**拉起必须三步，少一步就静默失败**：

```
taskkill /IM AUTO-MAS.exe /F      Electron 外壳会在后端死后继续活着，窗口
                                  看着好好的，实际没有任何调度
schtasks /end  /tn AUTO-MAS_AutoStart   外壳活着时任务算「正在运行」，
                                        /run 会返回 0x41301 什么都不做
schtasks /run  /tn AUTO-MAS_AutoStart
```

### 服务与计划任务的环境差异

服务不经过 `ark-relay.ps1`，而 `ARK_LOG_FILE` 一直是那个脚本设的、`.env` 里
没有。结果是服务跑得好好的却把日志写进虚空。现在这几个变量由 `service.py`
自己兜底设置（`PYTHONUTF8` / `PYTHONIOENCODING` / `ARK_LOG_FILE`）。

装服务时 pywin32 会把 `pythonservice.exe` 和 `pywintypes312.dll` 移动/复制到
AUTO-MAS 的内嵌 Python 目录，这是它自身机制。

## 关机与汇报

```
ARK_SHUTDOWN_AFTER_RUN=1       跑完关机，由中继执行（AUTO-MAS 两个队列都是 NoAction）
ARK_REPORT_BEFORE_SHUTDOWN=1   关机前必定先发一份当时进度
```

第二个开关是测试期用的：早上那轮跑完就关机，不发的话到晚上之前什么都不知道，
「刷了但没刷到东西」和「跑得好好的」看起来一模一样。测试结束、只信任晚上那条
日报之后，改成 0 即可。

这份临时汇报**不占用当天的日报名额**（`send_daily_now(mark=False)`），晚上那条
照常发。标题用 🔎 并带「（临时查看）」，跟正式日报的 📋 区分开。

**为什么不用定时任务发**：早上跑完就关机，定时任务得卡在「跑完」和「关机」
中间那个会移动的窗口里，做不可靠。关机前发是确定性的。

## 通知只有一条路

```
MAA   → 中继 → 企业微信
MAS   → 中继 → 企业微信
```

MAA 和 AUTO-MAS 的直连推送**全部关闭**，Server酱 也停用了——两条渠道都发到
微信，开着等于每条消息收两遍。

```
MAA gui.new.json    两套配置的 SendWhenComplete/Error/Stalled 全 false
                    注意 MAA 有 Default 和另一套用户配置，只改一套等于没改
AUTO-MAS Config.json  IfServerChan / IfSendMail / IfPushPlyer 全 false
中继 .env            SERVERCHAN_KEY 已注释
```
