# 架构

## 物理布局

```
        日本 (Asia/Tokyo, UTC+9)              中国 (Asia/Shanghai, UTC+8)
   ┌──────────────────────────┐          ┌──────────────────────────────┐
   │  MacBook Air             │          │  Windows 11  (朋友的机器)     │
   │  100.x.x.x           │◄────────►│  $ARK_HOST  "ins"        │
   │  <控制端主机名>             │ Tailscale│                              │
   │                          │   + SSH  │  每天开机约 3 小时后自动关机   │
   └──────────────────────────┘          └──────────────────────────────┘
              │                                        │
              │ 手机上也能操作                          │ 米家智能插座控制通电
              ▼                                        ▼
        Android 手机                              BIOS RTC 唤醒
```

**时差 1 小时。** 所有人类可读的时间都要标注是哪一边的时钟。

## 软件栈

```
AUTO-MAS  (v5.3.1, Electron + 内嵌 Python)
   │  调度队列 / 日志监控 / 失败重启 / 多账号配置 / 通知
   │
   ├─► MAA v5.1.0          明日方舟   ──► 雷电模拟器 (ldplayer, Index 1000)
   │                                        └─ ADB 控制，不占用系统鼠标
   │
   └─► MaaEnd v1.6.5       终末地     ──► Endfield.exe (Win32-Front)
                                            └─ 前台控制器，抢占鼠标，
                                               要求窗口最前且不被遮挡
```

**为什么用 AUTO-MAS 而不是自己写调度器**：它已经实现了定时队列、按日志判定失败、自动重启脚本、多脚本多账号配置、结构化运行记录。自己写过一版约 1000 行的 runner，功能是它的子集，已删除。

## 触发链

```
米家插座 08:40 断电 / 08:45 通电
   └─► 主板「AC 上电自启」→ Windows 开机
         └─► 自动登录到桌面（Administrator）
               └─► 计划任务 AUTO-MAS_AutoStart（登录触发）
                     └─► AUTO-MAS 启动（最小化到托盘）
                           └─► 09:00 定时 → 新队列：MAA → MaaEnd
                                 └─► 完成 → 关机

BIOS RTC 21:20 唤醒
   └─► （同上）→ 21:30 定时 → Evening-MAA：只跑 MAA
         └─► 完成 → 关机
```

链条上任何一环断掉，表现都是**什么都没发生、也没有任何通知**。这正是中继要解决的问题，见 [中继设计](04-中继设计.md)。

## 远程控制通道

| 通道 | 用途 | 限制 |
|---|---|---|
| SSH (Tailscale) | 文件、进程、配置、日志 | **单点故障**，坏了无法自救 |
| 计划任务 + PowerShell | 截图、鼠标键盘、启动程序 | 必须在交互式会话跑（session 0 隔离） |
| ToDesk / TeamViewer | 人工看画面 | **跑任务时不要用**，会遮挡游戏窗口 |
