# 手机页文案的规矩

**改 `web/app.js` 里任何一条 `hint` / `label` 之前先读这份。**

为什么有这份文件：2026-09-04，页面上的说明写成了这样——

> 上游 beta.5 那阵它是坏的（弹窗出来不点确认，重试三次全失败），
> v2.27.0-rc.1 已修好，中继在 09-04 开机时自动开了回来

用户的话是「太私人措辞了」，并要求比照 `提ISSUE的规矩.md` 立一条规矩。
这段话的问题不是不准确，而是**它写的是我的工作过程，不是这个开关的作用**。
页面是给人当遥控器用的，不是我的施工日志。

---

## 一条判据

> **只写「这个开关是干什么的、改了会怎样」。**
> 除此之外的一律不写。

一句话读完就知道该不该动它，就合格了。

## 不许出现的东西

| 不许写 | 为什么 |
|---|---|
| 上游、社区、issue 号、版本号、PR | 这是软件的来历，不是设置的作用 |
| 中继、脚本、母本、账本这类内部名词 | 用户面对的是游戏，不是我的代码 |
| 日期、「那次」「那阵」「实录」 | 事故编年史属于 `docs/`，不属于按钮下面 |
| 「我」「用户」「他说」 | 页面没有第一人称，也不转述对话 |
| 「已修好」「先关着」「等上游」 | 状态会变，写死在文案里就会过期变成谎话 |
| 感叹号、语气词、玩笑 | |
| **当前勾了什么、当前值是多少** | 控件自己就显示着，文案再写一遍，一改就变成假的。2026-09-04 写着「路线 3 和 13 已取消勾选」，用户把 16 条全勾上之后那句当场是谎话 |

## 该写的样子

* **主语是这个设置**，不是我，也不是某个程序。
* **现在时、陈述句**，说它的行为，不说它的历史。
* **有前提就写清楚**：「只在上面选 X 时才有用」。
* **有代价就写清楚**：数值、消耗、上限，例如「单倍每轮 80 理智，双倍 160」。
* 长度**一两句**。写不下的放 `docs/`，页面上只留结论。

对照：

| 改前 | 改后 |
|---|---|
| 上游 beta.5 那阵它是坏的……rc.1 已修好，中继开机时自动开了回来 | 理智不足时自动使用应急理智加强剂 |
| 勾上的才会去采。3、13 两条上游寻路走不到，先摘掉了；rc.1 说修了寻路，想验证就勾回来 | 勾上的路线才会去采。路线 3 和 13 目前寻路走不到，已取消勾选 |
| 哪几天采。没勾的日子它会立刻结束，日报里看着像秒完成，其实是没排班 | 只在勾选的星期执行。没勾的日子这个任务会立即结束 |
| 开着＝有活动就去刷活动关……826 那次刷错关就是它开着 | 开着＝有活动就刷活动关，活动结束后自动回到上面那个固定关 |

注意第二、三条：**该说的事实一个没少**（哪两条路线不采、没勾的日子会立即结束），
去掉的只是来历和我的口吻。**规矩不是让文案变简略，是让它只讲设置本身。**

## 这条规矩由闸门执行

`scripts/mac/lint-repo.sh` 会扫 `web/app.js` 里的 `hint` 和 `label`，
命中上表里的词就拒绝提交。**文档拦不住，闸门才拦得住**——
所以新发现的坏词要往闸门里加，不是只往这份文档里加。
