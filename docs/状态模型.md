# 中继的状态：现状清单与收口设计（根治第 3 项）

## 现状：35 种文件散在 `state/` 里，各模块自己读写

| 类别 | 文件 | 谁写 | 谁读 | 收口后 |
|---|---|---|---|---|
| 当天一次性标记 | `report-{day}.sent`、`interim-{day}.sent`、`banner-{key}.sent`、`alerted-{day}.json`、`hb-{day}.txt`、`tacet-shots-{day}.sent` | report / handle / banners / phone | 同左 + shutdown | `marks` 段：`{"report:2026-09-07": "时刻"}` |
| 开关和模式 | `skip-next-shutdown.flag`、`shutdown-skipped.txt`、`debug-until.txt`、`skip-{day}.flag`、`skip-restore.json`、`queue-skips.json`、`gameupdate-off.flag`、`maintenance-today.json` | modes / commands / phone | shutdown / engine / phone | `modes` 段 |
| 周常三门 | `annihilation.json`、`garden.json`、`weeklyboss.json` | 三个 gate | phone / service（新的一周） | `weekly` 段，三门同一形状 |
| 版本记账 | `code-version.txt`、`okww-version.txt`、`maaend-version.txt`、`inbox-version.txt`、`announced-version.txt` | selfupdate / okww_patch / preupdate / inbox | 同左 | `versions` 段 |
| 更新流程 | `preupdate.json`、`gameupdate.json`、`gameupdate-pending.json`、`arknights-client.json`、`maaend-collect-routes-off.json`、`maaend-disabled-for-1.5.3.json` | preupdate / gameupdate | 同左 | `updates` 段 |
| 告警队列 | `pending.json`、`resume-ids.json`、`seen.txt`、`phone-seen.json` | handle / inbox / phone | 同左 | `queues` 段 |
| 账本与证据（保留为文件） | `ledger-{day}.jsonl`、`evidence/`、`apk/`、`desktop/`、`shot-*.png`、`req/res-*.json`、`relay.lock`、`agent.*` | — | — | 不动：追加型/二进制/锁 |

问题不在文件多，在**没有一张字段表**：手机页、日报、关机判定各自去读各自那几份，
一处写晚了就出一个假状态（2026-09-07 周本「本周已打」为假就是这么来的）。

## 设计

* `ark_relay/statestore.py`：`StateStore(state_dir)`，唯一的落盘文件 `state/state.json`，
  原子写（临时文件 + replace），每次改动整份写；读的时候按 mtime 缓存。
  五个段：`marks / modes / weekly / versions / updates / queues`，每个键在本文件的
  字段表里登记（名字、类型、谁写、谁读、什么时候清）。**没登记的键写不进去**（和
  手机页 `set_config` 只改已存在字段一个规矩）。
* 现有的 `State`、`modes.*`、三个 gate、`preupdate.should_run/mark_run`、`gameupdate.pending`
  等接口**保持不变**，只把里面的文件读写换成 store 调用——调用方一行不改。
* 迁移：第一次启动时如果 `state.json` 不存在，把上表里的旧文件读进来生成，然后旧文件
  改名 `.migrated`；跑三天没问题再删。
* 手机页 `state_payload` 直接把 `weekly / modes / versions` 三段原样带上，页面显示的
  就是中继判定用的同一份数据。

## 顺序

1. `statestore.py` + 字段表 + 测试（原子写、未登记键拒绝、迁移）。
2. 周常三门换成 store（形状已统一，最容易）。
3. 当天标记与开关（report/interim/skip/debug）。
4. 版本记账与更新流程。
5. 告警队列。
每一步部署后上机看 `state.json` 和手机页对得上。
