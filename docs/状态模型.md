问题不在文件多，在**没有一张字段表**：手机页、日报、关机判定各自去读各自那几份，
一处写晚了就出一个假状态（2026-09-07 周本「本周已打」为假就是这么来的）。

## 设计

* `ark_relay/statestore.py`：`StateStore(state_dir)`，唯一的落盘文件 `state/state.json`，
  原子写（临时文件 + replace），每次改动整份写；读的时候按 mtime 缓存。
  五个段：`marks / modes / weekly / versions / updates / queues`，每个键在本文件的
  字段表里登记（名字、类型、谁写、谁读、什么时候清）。**没登记的键写不进去**（和
  手机页 `set_config` 只改已存在字段一个规矩）。
* 现有的 `State`、`modes.*`、三个 gate、`preupdate.should_run/mark_run`、`gameupdate.pending`
  等接口**保持不变**，只把里面的文件读写换成 store 调用——调用方一行不改。
* 迁移：第一次启动时如果 `state.json` 不存在，把上表里的旧文件读进来生成，然后旧文件
  改名 `.migrated`；跑三天没问题再删。
* 手机页 `state_payload` 直接把 `weekly / modes / versions` 三段原样带上，页面显示的
  就是中继判定用的同一份数据。

## 顺序

1. `statestore.py` + 字段表 + 测试（原子写、未登记键拒绝、迁移）。
2. 周常三门换成 store（形状已统一，最容易）。
3. 当天标记与开关（report/interim/skip/debug）。
4. 版本记账与更新流程。
5. 告警队列。
每一步部署后上机看 `state.json` 和手机页对得上。

## 做完了（2026-09-08）

`ark_relay/statestore.py`：`state/state.json`，六段，字段表 `FIELDS` 登记过的键才能写。
已搬进去的：

* `weekly`：剿灭、周常乐园、周本
* `marks`：日报、临时日报、卡池播报（按天/按卡池，通配键）
* `modes`：下一次别关机、被吃掉的关机机会、调试模式到期
* `versions`：OK-WW、MaaEnd、代码版本
* `updates`：预更新记账、游戏更新记账、待更新登记、总开关、方舟客户端版本、
  为更新摘掉的队列、今天的停服时段
* `queues`：待推送告警、手机指令去重、待办版本、跳过模式的恢复标记与当天跳过

**2026-09-08 补完的第二批**：`updates` 段又加了三条 MaaEnd 的临时关任务记录
（`maaend_disabled_1_5_3` / `maaend_reenable_next_boot` / `maaend_disabled_spmed`），
`queues` 段加了 `channels_down`。搬这三条时读写两侧必须一起改——清扫会把旧文件
改名成 `.migrated`，只加迁移不改读法的话记录永远读不到，那几项日常会一直关着没人知道。

**故意留作文件的**：`ledger-*.jsonl`（只追加）、`seen.txt`（只追加、会长很大）、
`evidence/`、`apk/`、`desktop/`、`shot-*.png`、`req/res-*.json`（二进制或传输产物）、
`relay.lock`（锁）、`agent.*`（要给别的进程读的脚本）、`hb-*.txt`（心跳，写得太勤）、
`asar-labels.json`（纯缓存，是派生数据不是状态，丢了自己会重建）。

现在没有任何状态绕过 StateStore。

迁移是自动的：`state.json` 不存在时把旧文件读进来，旧文件改名 `.migrated` 留着。
测试见 `tests/test_statestore.py`。
