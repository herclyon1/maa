# Silent-failure audit (2026-10-10)

Every place in `relay/ark_relay/` and `scripts/` where a failure is caught and
not raised, checked one by one on origin/main fed9a445: does the failure reach
the operator, and if not, does that change what they get?

## Scope

* All `except` handlers whose body neither logs at WARNING/ERROR nor raises
  (found with an AST scan: 853 handlers in total, 634 of them in scope), plus the
  `log.info(...)` lines outside an `except` that record a failure (22).
* Not repeated here: the switches that decide whether a logged fault is pushed
  (`errwatch.recovered()`, `group_pushed`, `going_down`, `relay_shutdown_issued`,
  `known_fixed`, `daily_only`). Their history, commit by commit, is in
  `~/Money/styl-work/BOARD/中继-静音审计-1010.md` (relay one, same day).
* Already fixed the same day, not redone: cc71a980 (shutdown snapshot),
  11e385a0 / 87864949 (AUTO-MAS exit during a Windows shutdown), 3e715160
  (MaaEnd no-exit run uploads its evidence), 372c24c1 / fed9a445 (WMI drop
  diag carries the SCM events).

## How a failure reaches the operator

* WARNING / ERROR on an `ark.*` logger: pushed to the group every time
  (errwatch.py docstring). With `extra=errwatch.recovered()`: daily report only.
* INFO / DEBUG: nobody. They stay in relay.log on the game machine.
* A returned error string / `problems` list: only if the caller pushes it; each
  row names the caller.
* scripts/: stdout/stderr and the exit code of the calling session.
* Normal states (resource short, already claimed, skipped by design) must not
  alarm: docs/NOTIFICATIONS.md.

## Standard

Google Python Style Guide 2.4.4: a catch-all is acceptable only at "an isolated
point in the program where exceptions are not propagated but are recorded and
suppressed instead" (https://google.github.io/styleguide/pyguide.html#244-decision).

* keep: recorded on a channel that reaches the operator, or harmless by nature
  (handle cleanup, best-effort evidence write, a parse fallback the caller treats
  as unknown, a probe retried until a reported timeout), and the fallback value
  is not passed off as real.
* fix: nothing reaches the operator, and it changes what they get: a task
  skipped, a wrong number / state / plan shown as real, an alarm not sent,
  state lost, a tool reporting success after a failure.

A fix that adds a WARNING on a path called every tick, on every phone-state
publish or in a polling loop says it once per condition (the existing pattern:
`WeeklyBossGate._last_error`, `Quota.mark_full`), since each WARNING is a group
message. Payload shapes the App parses are not changed.
