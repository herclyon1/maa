# 待办与设想

还没做的事，以及为什么当时没做。

## 安卓端开关：远程决定某个检查点要不要干活

**现状**：中继在固定的唤醒时刻（09:00 / 21:30）检查那个时刻有没有排期，
没有就关机。这条规则救了"队列暂停了但唤醒还在"的场景，
但它认不出"人正在维护这台机器"——
如果有人下午开机干活、一直挂到 21:30，机器会在他手底下关掉。

**已知会踩，暂时接受**。操作者的原话是「我知道这个可能会造成我正在维护但他自动关机了，
但是这个先不管我们之后能修」。

**想做的**：一个安卓小应用，能远程把某个检查点标成"今天别自己关"或"今天别跑"。

实现上不需要新通道 —— 现成的待办队列就够：

```json
{"action": "checkpoint", "time": "21:30", "skip_today": true}
```

App 要做的只是往 GitHub 那个文件写一行，和现在手改是同一条路。
难点不在中继侧，在于 App 要拿一个能写仓库的令牌，
而令牌放在手机上这件事要想清楚怎么存。

## 让告警真正实时

**现状**：AUTO-MAS 要到整个脚本结束才把所有尝试一次性写盘，
所以一次 09:17 的登录失败，中继要到 09:58 才可能知道 —— 迟了 41 分钟。
中继自己从"文件出现"到"推送出去"只用 34 秒，压不动了。

**想做的**：直接盯 MaaEnd 的实时日志（它是边跑边写的），
失败那一行一出现就推。代价是多一个数据源，两边可能对不上，
要想清楚以谁为准。

## 让那台没有管理员权限的 Windows 可远程操作

**结论：Tailscale 这条路是死的。**
`--tun=userspace-networking` 能绕开网卡驱动，但 tailscaled 创建控制管道时
会强制把所有者设成管理员组 SID，普通用户无权指派：

```
namedpipe.Listen: open \\.\pipe\ts-human:
  This security ID may not be assigned as the owner of this object.
```

换过 `--socket` 到非保护路径，同样被拒。**别再试了。**

`cloudflared` 单文件能在普通用户下跑起来（已验证 version 2026.8.2），
但它只是隧道 —— 需要本地有个服务可以转发，
而装 sshd 同样要管理员。所以"能连上"这件事仍然没有解。
