# 维护手册

给我自己看的：怎么部署、怎么改配置、提交前跑什么。
（README 是给人看的项目介绍，操作内容一律放这里。）

## 部署

中继部署到游戏机。它自己会跑全套测试、重建清单、逐个核对哈希、重启服务并确认起来了：

```bash
export ARK_HOST=100.65.39.119
scripts/mac/deploy-relay.sh
```

跑之前必须先写 `relay/RELEASE-NOTES.md`——那段文字就是推到手机上的更新说明，
不写会被拒绝部署（`lint-repo.sh` 第 5 项）。部署成功后它会自动清空，所以
**清单里 RELEASE-NOTES.md 的哈希和磁盘对不上是正常的**，第 14 道闸门排除了它。

手机页发布到 GitHub Pages：

```bash
scripts/mac/deploy-web.sh
```

改完代码只 push 不 deploy 的话，机器拿不到——清单和代码对不上时开机自更新会
认为「本机和清单一致」，不下载、不报错。第 14 道闸门就是拦这个的。

## 改配置

**不要直接编辑机器上的配置文件。** 三个游戏的配置有母本和副本之分，改错那份等于没改；
终末地和鸣潮的快速配置是关的，从 AUTO-MAS 侧改它们不生效。

* 规程：[CHANGE-CONFIG.md](CHANGE-CONFIG.md)
* 配置清单：[CONFIG.md](CONFIG.md)
* 查真正生效的值：`scripts/mac/winrun.sh --py scripts/mac/lib/effective_config.py`

日常改设置走手机页；命令行改走 `queue/config.json`（抬版本号，中继下次开机整批应用）。
**那个文件是整份重放**，写新指令前先把上一条删掉，否则旧指令会跟着一起执行。

## 提交前

两个硬闸门，都要绿：

```bash
scripts/mac/lint-repo.sh
```

```bash
scripts/mac/guardcheck.sh
```

前者 14 项：shellcheck、不许用 PowerShell 5.1、测试全绿、无死代码、静态检查、
手机页文案规矩、测试语料入库、外部不许写中继状态、公开仓库不许有他人身份、
文档和脚本都要有入口、部署清单和代码一致。
后者验证那些闸门本身还活着——闸门坏了不出声比没有闸门更糟。

## 手动跑一趟

```bash
scripts/mac/run-one.sh MAA|MaaEnd|OK-WW
```

唯一正门，内含忙闲闸门。禁裸调 `/api/dispatch/start`、禁 `taskkill`。
