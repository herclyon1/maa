## 两个独立的毛病

### 一、MTU 黑洞 —— "有 Wi-Fi 但什么都打不开"

| 项 | 实测值 |
|---|---|
| 电视棒 `wlan1`（设备连的那一侧） | **MTU 1500** |
| 电视棒 `eth0` | **MTU 1500** |
| **真实路径 MTU**（从电视棒 `ping -M do` 探出） | **1460**（1460 通、1468 不通） |
| 楼里路由器 DHCP 是否下发 MTU | **没有**（`LinkProperties … MTU: 0`） |

**为什么是 1460**：DS-Lite 把每个 IPv4 包套进 IPv6 送出去，IPv6 包头 40 字节，
`1500 − 40 = 1460`。这是算术，不是巧合。

1461–1500 字节的包被静默丢弃，"需要分片"的 ICMP 又回不来 → **PMTU 黑洞**。
小包（ping / DNS / TLS 握手开头）全通，所以图标显示"已连接"；大包（网页正文、
视频、游戏数据）全丢。**所有设备一起中招，因为默认都是 1500。**

- **为什么以前好好的**：楼里换到 DS-Lite（或换了路由器）那天开始的。
- **为什么挂 WARP 就能用**：WARP 隧道 MTU 1280，把包压小了，等于绕开黑洞——
  **不是"加速"**。
- **为什么有时几分钟几小时自己好**：推测是系统缓存的路径 MTU 过期后重新探测，
  偶尔探对了。**这条没抓到现场证据，只是推测。**

### 二、百兆封顶

logcat 里网卡自报家门：

```
USB device attached: vidpid 0bda:8152
mfg/product: Realtek / "USB 10/100 LAN"
```

`0bda:8152` 是 **RTL8152，百兆芯片**（千兆是 `0bda:8153`）。实测下载 10.8 MB/s
≈ 86 Mbps，正好是百兆扣掉开销的满速。

**但这个百兆口不是瓶颈——LEONET 的线路本身就是最大 100Mbps。** 日文资料一致：
レオネット 采用 **VDSL方式** 或 **LAN配線方式**，两者上限都是 100Mbps。
所以 86–90 Mbps **就是这条线的满速，已经拿满了**。

**推论：换千兆扩展坞、换千兆路由器，速度上零收益。别为了提速花这个钱。**

（2026-08-25 的记录：我一度只验证了"棒子是百兆"就推断"线路可能是千兆、
用户只用到十分之一"，那是错的——没去查 LEONET 的服务规格。
教训见 [PITFALLS.md](PITFALLS.md) 与 `trust-the-log-over-plausible-theories`。）

## 已经排除的（别再试第二遍）

| 试过什么 | 结果 |
|---|---|
| 换 DNS（阿里 / DNSPod / 1.1.1.1） | 三个 CDN 节点本来就 0% 丢包 6–16ms，**烂的只有游戏网关**；网关 IP 由服务器列表下发，DNS 换不掉 |
| IPv6 绕路（针对国服游戏） | 鸣潮域名**全部没有 AAAA 记录**，且客户端拿不到 v6 出口 |
| 远程连乌鲁木齐那台机器打游戏 | 东京→乌市 均值 307ms、峰值 1131ms、5% 丢包，动作游戏不可玩 |
| WARP | 只是把包压小，副作用是绕远，还带断过远程 |
| 免 root 改电视棒 MTU | `ip link set` / `ndc setmtu` / `cmd wifi` / `settings` 全部拒绝或不存在 |

**国服游戏卡是另一件事**：`traceroute` 显示日本境内 6 跳全部 <22ms 零丢包，
一进中国电信 163 骨干（`202.97.x`）就 1500ms。那是电信国际出口拥塞，
**跟 MTU 和这根棒子都无关**，家里改什么都治不了。

## 可选方案

前提事实：**Leopalace 允许住户自己接路由器**，这是住户里的常规做法。日文攻略
普遍指出 **LEONET 的速度瓶颈就是 Life Stick**，把墙上的网线改接自己的设备即可提速；
租房中介当初也这么说过。

> **先明确：绕过电视棒不会提速**，LEONET 本身就是百兆。下面两个方案解决的是
> **手机的 MTU** 和**棒子的不稳定**，不是速度。所以**买最便宜的百兆转接头就够**。

### 方案 A：USB-C 网口转接头 + Mac 共享（只有两台设备时的最优解）

转接头插 Mac，Mac 直连墙口，再用 macOS「互联网共享」把网络分给手机。

- **手机的 MTU 自动修好**：现在 ICMP"需要分片"从上游传不回来所以设备学不到 1460；
  Mac 当路由器时**那条 ICMP 由 Mac 自己发出，一跳就到手机，不可能被过滤**，
  手机会自动学到正确的 MTU，**不需要在手机上改任何东西**。
- 代价：Mac 必须开着。
- 苹果日本有卖 Belkin USB-C to Gigabit / 2.5Gb Ethernet（可走苹果退货政策），
  但**线路只有百兆，2.5G 那款是浪费**。

### 方案 B：自己买路由器

消费级路由器**默认就做 MSS 钳制**，所以全家设备自动修好，Mac 也不用开着。
各家（Buffalo / TP-Link / Elecom / NEC Aterm / IODATA / ASUS）都有 LEONET 下的
设置教程。

**不用买千兆**：LEONET 上限就是 100Mbps（日文实测换完路由器是 82Mbps 下行，
与此吻合）。买台便宜的就行。

### 方案 C：治电视棒本身 —— 不建议

- **root 走不通**：`sys.oem_unlock_allowed=1`（能解锁），但解锁后**没有原厂 boot
  镜像可打补丁**；`boot_a` 是 `brw------- root root` + SELinux Enforcing，
  adb（uid 2000）读不了；搜遍网络**没有 ts401 / TVcore / LEONET 的公开固件**。
- **刷 Linux 不现实**：SoC 是 Amlogic S4（S905Y4 一族），`ophub/amlogic-s9xxx-armbian`
  的支持列表里**没有 S905Y4**，主线内核对 S4 的支持还在开发中。ARM 盒子不像 x86，
  **每块板子都要有自己的设备树 DTB**，这台 ODM 棒子没有公开 DTB。Wi-Fi 是博通 SDIO
  （`bcmsdh_sdmmc`），AP 模式在主线下大概率起不来 → **有线能用、Wi-Fi 没了**。
- **备份是可能的，但要另一套家伙**：Amlogic **maskrom 模式**（按住棒子上的 RESET）
  + USB 公对公线 + Windows 电脑，用 `update mread store <分区> normal <起始> <大小>
  <输出文件>` 把分区读出来。**这是刷机前唯一的退路**，adb 做不到。

## 怎么连上电视棒（下次直接用）

电视上：设置 → 系统 → 关于 → 连点「Android TV OS build」7 次 → 开发者选项 →
打开 **USB 调试**。然后：

```bash
adb connect 10.76.139.46:5555     # 注意是 eth0 那一侧，热点侧的 5555 不开
```

电视上勾「一律允许」。platform-tools 直接下，不用装 brew：
`dl.google.com/android/repository/platform-tools-latest-darwin.zip`

连上之后能读：`ifconfig -a`（各接口 MTU）、`dumpsys wifi`（SoftAP 状态）、
`ip neigh`（谁连着）、`logcat`（网卡型号、tethering 事件）、
`ping -M do -s N`（真实路径 MTU）。**改不了任何东西**，uid 2000 没有 CAP_NET_ADMIN。

## 当前设置

Mac：`sudo networksetup -setMTU en0 1460`。实测 1460 带 DF 标志 20 包 0% 丢包，
下载 9.6–10.8 MB/s；1200 是 9.0–10.2 MB/s，**差别在噪声范围内，两者都跑满了百兆口**。
1460 是精确上限零余量，哪天再犯病就降到 1400。
