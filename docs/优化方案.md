## 第一档：不做就还会出事

### 1. 关机决策要出声，「别关机」开关要有时效
**问题**：`_maybe_shutdown` 的 8 道门任何一道说「不关」，只写 relay.log。
09-03、09-04 连续两晚机器白开一夜，原因是我没取消的 `skip-next-shutdown.flag`，
它**没有时效**，而且没有任何东西会告诉你「今晚不关机了，因为 X」。
本该兜底的 GitHub Actions 开机监督又是关着的。
**做法**：
- 到了本该关机的时刻却没关，**推一条**「今晚不关机：原因」（事件驱动，一天最多一条，不是轮询）。
- `skip-next-shutdown.flag` 写入时带过期时间：只对**当天下一次**关机有效，过了当天自动作废；开机时发现是隔夜的直接清掉。
- 把「别关机标记 / 调试模式 / 下一次关机机会」并进 `healthcheck.py`，收工体检一眼看到。
- 关机判定从 `engine.py` 拆成 `shutdown.py`：一个纯函数 `decide(now) -> (关不关, 原因)`，原因就是推送文案；`test_shutdown.py` 直接测它。
- 开机监督：你把三个 Secrets 配上，我把 `enabled` 改 true，`pause_until` 改成读调试模式。

### 2. 清理「欠的活」并给每条挂触发条件
**问题**：15 条未勾里，「09-04 方舟大版本维护日」已过去、「队列改名+通知样式」多半已做、
「1.5.3 适配」要看 MaaEnd 出没出新版。你问过「你记不住事吗」，账本本身过期就等于没记。
**做法**：现在逐条核实、该勾勾该删删；留下的每条必须写「**下次看它的条件**」
（某版本发布 / 某天早班跑完 / 你说一句话），没有条件的不许留。
上游 issue/PR（#5506、#5453、beta.6）做一个 `scripts/mac/upstream-watch.py`，
**我要看时**一条命令拉全状态，不定时跑。

**问题**：同一条教训在 PITFALLS、RETROSPECTIVE、TOOLING、CLAUDE.md、memory 里重复两三遍，
每次会话光规矩就吃 22KB，而重复犯错并没有因此变少——你自己说过「写进文档里跟放屁一样」。
**做法**：

  **一句话**放 CLAUDE.md；**背景故事**放唯一一篇中文《教训》，PITFALLS 和 RETROSPECTIVE 合并进去。
- memory 的 31 条「死命令」按主题合并到十条上下（例如「他说什么就做什么」「活没干完不许停」「不许说否定词」是一条），
  合并时保留原文出处。

## 屎山怎么改（2026-09-06 夜，用户问「那现在这个软件要怎么改」）

不砍功能、不冻结，在原地把它改成「改一处能知道影响哪里」的东西。顺序不能换：

1. **先立防线，再动结构**：真实一天的回放测试。把已经跑过的真实一天
   （AUTO-MAS history + 三个程序的日志 + 当天的推送和关机决定）存进 `relay/tests/replay/`，
   中继回放它，必须产出一模一样的推送文案和关机判定。以后每修一个 bug 就把那一天存进来。
   这是屎山唯一缺的东西：能证明「改了 A 没坏 B」。现在的 64 个测试是手编输入，证明不了这个。
2. **按缝切，不重写**：`engine.py` 拆成三块纯函数——记账（_handle）、报告（日报/临时查看）、
   关机判定（返回「关不关 + 原因」）；`service.py` 的 main 拆成开机阶段函数；
   `okww_patch.py` 一个补丁一个文件。每一步都只搬不改，回放测试全过才算搬完。
3. **注释里的事故史搬出代码**：代码只留一句「为什么这样写」，故事进 docs。
   现在一半行数是历史，读代码的人分不清哪句是规则哪句是往事。
4. **改动节奏**：改前跑回放，改后回放全过才部署；一天最多部署一次，除非真实早晚班失败。
5. **指标**：日报末尾「连续 N 天你没动过它」。

工作量：第 1 步一个工作日，第 2 步一个工作日，第 3 步零散做。
