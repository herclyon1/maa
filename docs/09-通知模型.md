# 09 - 通知模型（权威）

> 用户 2026-08-20 口述、当场复述确认。**这是通知行为的唯一权威定义**，
> 代码与其他文档若有出入，以本页为准。

## 一、三种汇总通知

| # | 名称 | 什么时候发 | 标题样式 | 说明 |
|---|---|---|---|---|
| 1 | **正式汇总** | **晚班队列跑完之后**，每天一次 | `📋 08-20 · 全绿 ✅` | 当天的正式日报。这是**常态下唯一**的一条汇总 |
| 2 | **临时查看** | **白天队列跑完之后** | `🔎 08-20 · …（临时查看）` | **仅测试阶段存在**。中继稳定后可以关掉，正式汇总不受影响 |
| 3 | **手动执行** | **手动触发的队列跑完之后** | `🔎 08-20 · …（手动执行）` | 必须**明确标注是手动跑的**，与前两者区分 |

三者**互不占用名额、互不抵消**：

- 临时查看和手动执行都**不消耗当天的正式汇总**——晚上该发的正式日报照发。
- 白天跑了几轮就发几条（每轮收尾各一条），不是每天一条。
- 手动补跑一轮，就单独再发一条并标「手动执行」。

## 二、其它即时通知（不属于汇总，不受上面规则约束）

| 事件 | 行为 |
|---|---|
| 任务失败 | 等重试全部结束后推一条（附模型写的人话诊断） |
| 重试后自愈 | 推一条「本次自愈，问题未解决」——自愈≠没问题 |
| 任务成功 | **静默记账**，不推送 |
| 该跑没跑 / 缺项 | 立刻告警 |
| 配置指令已应用 | 推一条回报（收件箱 v 号 + 改了什么） |
| 推送渠道故障 | 用还活着的渠道告警（如企业微信 60020 附当前出口 IP） |

## 三、每条汇总必须携带

- 关卡 / 掉落 / 理智 / 起止时间（双时区：服务器 + 东京）
- **当期活动剩余时间与倒计时**（读 MAA 自己的活动缓存）
  - 不足 36 小时加 ⚠️
  - 活动已结束且主关卡仍是活动关 → 明确提示"下一轮必失败，立即换关"
- 明日安排（跑什么、刷哪关、理智怎么用）

## 四、关机

- 中继在**队列跑完且日报已送达**后自动关机，这是既定设计，保留。
- **人（我）不得在没有用户明确命令时手动关机。** 2026-08-20 深夜有过一次
  自作主张关机，导致随后要还原配置时够不着机器。
